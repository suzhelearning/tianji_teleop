# SPARK Feedforward Joint-Limit Consistency Design

## Problem

Live telemetry shows the left J7 velocity-QP reference stopping at its safe
lower limit `-1.5208 rad`, while the upstream jerk-limited SPARK feedforward
reference reaches `-1.56916 rad`. The SPARK position IK already respects the
same `0.05 rad` margin as the velocity QP, but the feedforward reference clamps
only to the physical robot limits. Its strong joint-reference objective then
pushes into the QP bound and causes repeated active-bound and jerk reversals.

## Design

Keep the velocity QP, gains, and numerical joint velocity/acceleration/jerk
limits unchanged. Give `SparkFeedforwardReference7` the active
`JointLimitConfig` and use `computeJointVelocityBounds()` to constrain every
integrated reference step. This reuses the exact position-margin, velocity,
acceleration, braking, and hard-jerk feasible set used by the velocity QP.

The requested acceleration remains generated by the existing critically
damped tracker. Its candidate next velocity is clipped to the shared feasible
velocity interval; acceleration and jerk are then recomputed from that clipped
velocity. The position is integrated only after this projection, so the
feedforward state never enters the QP-excluded margin and does not require a
post-integration hard clamp.

## Scope

- Affect only SPARK feedforward reference construction and stepping.
- Preserve all configured limit magnitudes and normal-region gains.
- Preserve historical non-feedforward algorithms.
- Add a regression test that drives a reference toward a margin-protected
  lower limit with inward velocity and checks position, velocity, acceleration,
  and jerk at every cycle.
- Validate with focused tests, all tests, and the recorded PICO trace.
- Do not commit changes.
