## 20,000 样本求解器基准

命令：

```bash
./build/tianji_qp_ik_benchmark \
  --config config/qp_ik.yaml \
  --model models/marvin_m6_qp_test.xml \
  --samples 20000 --seed 20260809 \
  --output build/benchmark_results.csv
```

数据集哈希：`0xcd8409be5d486461`。每个样本包含左右两个 QP，五类工况均衡分布：名义运动、关节极限、近奇异零位独立微扰、不可达目标和连续轨迹。精确零位左右臂 Jacobian 的最小奇异值均为 `7.98186e-12`。冷启动和 1000 次 warm-up 不计入循环统计。OSQP 使用最大 3000 次迭代、绝对/相对容差 `1e-9`、关闭 polish；qpOASES 每臂使用最大 50 次 working-set recalculation 和 350 µs 内部墙钟保护。

qpOASES 3.2 的 `getCPUtime()` 实际基于 `gettimeofday()`。两个串行求解器的名义上限合计 700 µs，为同周期中的目标、运动学、安全验证和发布保留约 300 µs；初始化阶段已经求得的首个解仅在随后问题逐元素完全一致时直接复用，避免首周期重复 hotstart。外层仍用 `steady_clock` 统计完整计算周期，并由 Viewer 的 `CLOCK_MONOTONIC` 绝对期限记录真实调度超期。

本次基准的正确性结果：

- 两后端 solver/bound/完整周期/单臂周期 failure 均为 0；
- 最大解差 `1.353660e-6`，最大目标函数差 `1.43e-10`；
- OSQP 最大投影 KKT 残差 `1.287e-9`，最大边界违反 `1.628e-9`；
- qpOASES 最大投影 KKT 残差 `4.996e-16`，最大边界违反 `6.997e-13`；
- 两后端完整周期 p99 均低于 1000 µs；
- 本次发布运行中 OSQP 的 `over_budget_samples` 为 2/20000，qpOASES 为 0/20000；它只表示计算时长是否超过 1 ms，不冒充 Viewer 绝对期限线程记录的实际调度 deadline miss；
- 在两后端正确性均通过后，按完全相同 QP 回放的双臂求解 p99 选择：qpOASES 为 `17.335 µs`，OSQP 为 `227.499 µs`，因此选择 qpOASES。独立闭环轨迹的完整周期只验证 1 kHz 预算，不参与后端排名。

补充统计：OSQP 每臂 update/solve/求解器总耗时 p99 分别为 `2.314/116.056/118.226 µs`，平均迭代 `202.507`；qpOASES 分别为 `0.303/9.509/9.656 µs`，平均 working-set recalculation `2.570`。OSQP/qpOASES 单臂冷初始化均值分别为 `20.133/31.564 µs`。

## Viewer 与线程验收

- `test_snapshot_exchange` 验证有界队列满时立即返回、慢消费者不会阻塞生产者，并发样本无撕裂；
- `--telemetry FILE` 验证控制线程非阻塞入队、独立线程写 CSV，3 秒运行产生连续遥测且丢弃数为 0；
- headless 场景在绝对 1 ms 期限线程中逐项遍历手动、圆、8 字、纯姿态、组合、暂停/恢复、名义位复位和两个后端；每条命令均等待控制线程 ID 回执及对应状态，最终 `completed_stage=9`、`last_command_id=11`，控制/命令失败和两类队列丢弃均为 0；
- GLFW Viewer 分别以 `--solver osqp` 和 `--solver qpoases` 创建真实窗口、渲染独立 `mjData` 并按 `--duration 1` 正常退出；
- 控制线程退出后先 join，再释放渲染模型、场景、上下文和 GLFW。

## 结论与边界

V1 的 MuJoCo 运动学 QP-IK 通过既定正确性和 1 kHz p99 计算预算验收，默认后端为 qpOASES。当前完整双臂周期 p99 为 `132.930 µs`，运动学并非瓶颈，因此 V1 不增加 Pinocchio 依赖；后续加入逆动力学、碰撞或实机控制后可按 profile 结果引入 Pinocchio C++。

这不是实机安全认证。当前结果不覆盖关节动力学、力矩/加速度约束、真实 PD、摩擦与负载参数、通信时延、Pico VR 映射、碰撞或硬件急停；这些属于下一阶段。
