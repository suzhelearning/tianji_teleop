# PICO2 裸手路线隔离移植

## 范围与状态（2026-09-17）

目标：新增 PICO2 裸手骨架／手势输入，最终支持仿真与真机；保留现有
VR＋Manus、外骨骼、SPARK、mapped-palm 和所有驱动。默认入口不变。
实施阶段不提交；2026-09-17 用户授权审查、更新文档后本地提交，不 push。
本轮审查不操作设备。RL 模型推理不在本次迁移范围。

当前已接通独立 MuJoCo 仿真入口 `pico2_sim.sh`，通过合成输入／假 TCP 无窗口测试，
用户已完成真实 PICO 输入仿真录制；抖动与跟踪误差仍是已知限制，
不宣称性能验收完成；真机入口未开放。抗抖实验已按用户要求移除，仅原版 V131。
Python 参考用于回归，不代表最终控制热路径已完成 C++ 化。

## 两个 APK 与入口隔离

| 路线 | 头显应用／传输 | 手部来源 | 状态 |
| --- | --- | --- | --- |
| 既有 VR | whole-body／手柄 APK → driver/M0/TJVR | Manus 或外骨骼 | 原入口保留 |
| 新增裸手 | 手部跟踪 APK → TCP 10002 | 同一帧的 PICO 26 点 | 观察入口已实现 |

两个 APK 不合并。启动显式选一路，不自动切换、不混合两路的头显和手部数据。
观察入口不配置 ADB、不启动旧驱动或执行器。正式启动接线须新增输入所有权检查；
当前观察入口尚不代替现场互斥管理，操作前须自行停止旧输入会话。

## 数据与算法契约

1. 原始层：保留完整包、HMD、双手腕、26 点、有效性、源时间、本机接收时间、
   receiver 身份、连接代次和序号。源时间只作排序，不与本机单调时钟相减。
2. 手部：严格沿用 26→21 索引、Y 反射及绕腕 1.10 几何缩放。
   原始点与 retarget 输入分开，保留 source 官方 Hand2 worker 的模型、配置和滤波。
   不能直接替换成目标现有 Manus bridge 并宣称等价。
3. 机械臂：HMD 当前坐标系下的 Wrist → `head_palm_direct` → V131。
   该 mapper 名称虽含 palm，输入实际为 Wrist；需保留 tracked-to-TCP、基变换、
   左右姿态补偿和平移配置。仍用裸手相对头显输入，不替换为 mapped-palm 世界坐标输入。
4. C 为可选：未按过 C 使用来源固定映射，不额外要求标定。
   按用户最新要求，主动 C 改为 X/Z 标定：双手向前水平伸直，以 V131 FK
   的 J2=-90°、其余为零的 TCP 为参考；左右独立固定偏移，Y/姿态不变。
   沿用稳定采样门控，增加 1 m 偏移上限；失效或超时保留之前有效结果；
   首次标定失败且无旧结果时，必须重试成功后才能接管。采样中拒绝启动。
   重连／身份变化后不得沿用未经验证的新鲜度和接管权限。
5. IK：新增 `pico_ee_dexhand_qp` 的完整 C++ V131 路线，非 mapped-palm 改名。
   保留 Cartesian OTG、自适应伺服、QP、模型状态、TCP、时间戳和重置语义。
   内部 Cartesian OTG 与外部可选关节 Ruckig 分开。
6. 手势：当前为 21 点几何启发式 open/fist/pinch/unknown，非学习模型。
   标签只能观察；不得等同急停或自动授予真机使能。

## 接线与安全

最终独立选择裸手输入后，才连接既有执行层；复用 TJRCv2 54 关节顺序和协议，
但需另带版本化的来源、校准和新鲜度元数据，不伪造 ready。
失效侧不能因另一侧更新而续期；重复帧不能刷新接管资格。

仿真保持 S 接管、H 回 Home、到位且静止后自动准备、手动 R 保留，回程拒绝 S。
真机目标流程：未使能 → 可选 C（若主动发起须完成）→ Enter1 慢速对齐 → 到位静止 → Enter2 遥操
→ Enter3 回 Home/失能。退出、源失效和故障沿用既有门控，不绕过限位或反馈检查。

**来源 V131 快速配置明确仅供仿真。** 真机需单独受限配置，遵守目标执行器速度、
单步变化和使能保护；不能直接将 4 rad/s 快速配置用于硬件，也不能为了流畅放宽保护。
真机运动必须另有现场授权、预检与验收。
